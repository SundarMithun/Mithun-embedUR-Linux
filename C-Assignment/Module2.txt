#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <unistd.h>

typedef struct {
    int *arr;
    int size;
} array;

void *sum_prime(void *arg)
{
    array *a = (array *)arg;

    int *res = malloc(sizeof(int));
    *res = 0;

    for (int j = 0; j < a->size; j++)
    {
        int flag = 0;

        if (a->arr[j] < 2)
            continue;

        for (int i = 2; i * i <= a->arr[j]; i++)
        {
            if (a->arr[j] % i == 0)
            {
                flag = 1;
                break;
            }
        }

        if (flag == 0)
            *res += a->arr[j];
    }

    pthread_exit(res);
}

void *printt1(void *args)
{
    char *ch = (char *)args;

    for (int i = 0; i < 5; i++)
    {
        printf("%s\n", ch);
        fflush(stdout);
        sleep(1);
    }

    return NULL;
}

void *printt2(void *args)
{
    char *ch = (char *)args;

    for (int i = 0; i < 5; i++)
    {
        printf("%s\n", ch);
        fflush(stdout);
        sleep(1);
    }

    return NULL;
}

int main()
{
    int arry[5] = {4, 2, 7, 9, 5};
    int n = 5;

    char *pt1 = "Thread 2 is running";
    char *pt2 = "Thread 3 is running";

    array ar = {arry, n};

    pthread_t t1, t2, t3;

    pthread_create(&t1, NULL, sum_prime, &ar);
    pthread_create(&t2, NULL, printt1, pt1);
    pthread_create(&t3, NULL, printt2, pt2);

    int *res;

    pthread_join(t1, (void **)&res);
    pthread_join(t2, NULL);
    pthread_join(t3, NULL);

    printf("Sum Result: %d\n", *res);

    free(res);

    return 0;
}

a)Child Process-fork()
A child process is a new process created by an existing process, known as the parent process. 
In Linux and UNIX-based operating systems, a child process is created using the fork() system call.
When fork() is executed, the operating system creates a copy of the parent process. 
The newly created process is called the child process and receives its own Process ID (PID).

After a successful fork(), both the parent and child processes continue execution from the same point in the program. 
The return value of fork() helps distinguish between them:

Returns 0 in the child process.
Returns the child's PID in the parent process.
Returns -1 if process creation fails.

Child processes are widely used in multitasking environments where multiple tasks need to run simultaneously.
For example, a web server may create a child process to handle each client request while the parent process continues listening for new connections.

b)Handling common signals
Signals are software-generated notifications sent to a process to inform it that a specific event has occurred. 
They act as a communication mechanism between the operating system and running processes.
SIGKILL (Kill Signal)

Forcibly terminates a process immediately. This signal cannot be caught, blocked, or ignored by the process.

SIGALRM (Alarm Signal)

Generated when a timer set using the alarm() function expires. It is commonly used for implementing timeouts.

SIGUSR1 (User-Defined Signal 1)

A custom signal available for communication between processes. Its purpose is defined by the programmer.

SIGUSR2 (User-Defined Signal 2)

Another user-defined signal similar to SIGUSR1, used for application-specific communication.

SIGCHLD (Child Status Changed Signal)

Sent to a parent process when one of its child processes terminates or changes state. It helps the parent manage child processes.

SIGHUP (Hangup Signal)

Originally generated when a terminal connection was closed. It is often used to notify a process to reload its configuration.

SIGPIPE (Broken Pipe Signal)

Occurs when a process attempts to write to a pipe or socket whose reading end has been closed.

c)Exploring different kernel crashes

The kernel is the core component of an operating system responsible for managing memory, processes, devices, and system resources.
A kernel crash occurs when the kernel encounters a critical error from which it cannot safely recover.

Invalid Memory Access

When the kernel tries to access unauthorized or corrupted memory locations, it may trigger a crash.

Null Pointer Dereference

This occurs when the kernel attempts to access memory through a null pointer. Since the pointer does not refer to a valid memory location, execution fails.

Stack Overflow

If a kernel function uses excessive recursion or allocates too much data on the stack, the stack space may be exhausted, leading to a crash.

Device Driver Bugs

Faulty or improperly written device drivers are among the most common causes of kernel crashes because drivers operate in kernel space with high privileges.

Deadlocks

A deadlock occurs when multiple processes or threads wait indefinitely for resources held by each other, causing the system to freeze.

d)Time Complexity

Time complexity is a measure of the amount of time an algorithm takes to execute as the size of the input increases.
Time complexity is usually expressed using Big O notation, which describes the growth rate of an algorithm.

O(1) – Constant Time

The execution time remains the same regardless of input size.

Example:
Accessing an element in an array using its index.

O(n) – Linear Time

Execution time increases proportionally with the input size.

Example:
Searching for an element in an unsorted array.

O(log n) – Logarithmic Time

Execution time grows slowly as input size increases.

Example:
Binary Search.

O(n log n)

Example:
Merge Sort and Heap Sort.

O(n²) – Quadratic Time

Execution time increases rapidly as input size grows.

Example:
Bubble Sort and Selection Sort.

e)Locking Mechanism-Mutex/Spinlock

Mutex(Mutual Exclusion)
A mutex is a synchronization mechanism that allows only one thread to access a shared resource at any given moment. 
When a thread locks a mutex, other threads attempting to acquire the same mutex are blocked until it is released.

Example:
#include <stdio.h>
#include <pthread.h>

int count = 0;
pthread_mutex_t lock;

void *increment(void *arg)
{
    for(int i = 0; i < 100000; i++)
    {
        pthread_mutex_lock(&lock);

        count++;

        pthread_mutex_unlock(&lock);
    }

    return NULL;
}

int main()
{
    pthread_t t1, t2;

    pthread_mutex_init(&lock, NULL);

    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("Count = %d\n", count);

    pthread_mutex_destroy(&lock);

    return 0;
}

Spinlock

A spinlock is another synchronization mechanism where a thread repeatedly checks whether a lock is available instead of going to sleep.

Example:
#include <stdio.h>
#include <pthread.h>

int count = 0;
pthread_spinlock_t spin;

void *increment(void *arg)
{
    for(int i = 0; i < 100000; i++)
    {
        pthread_spin_lock(&spin);

        count++;

        pthread_spin_unlock(&spin);
    }

    return NULL;
}

int main()
{
    pthread_t t1, t2;

    pthread_spin_init(&spin, PTHREAD_PROCESS_PRIVATE);

    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("Count = %d\n", count);

    pthread_spin_destroy(&spin);

    return 0;
}
